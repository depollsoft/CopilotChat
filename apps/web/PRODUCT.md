# Product

## Register

product

## Users

CopilotChat is for developers and technical users who want a local-first, installable Copilot chat workspace with the familiarity of modern assistant products and the control of a local tool. They use it to keep conversations, projects, skills, MCP tools, workspaces, artifacts, imports, and provider settings close to the task they are doing.

## Product Purpose

The web app exists to make GitHub Copilot feel like a persistent, controllable workspace instead of a transient prompt box. Success means users can start or resume a chat, attach context, manage projects and tools, respond to agent interactions, and understand provider state without losing their train of thought.

## Brand Personality

Quiet, capable, local-first. The interface should feel calm under long-running work, confident around technical controls, and personal enough to make local ownership obvious without becoming cute or chatty.

## Anti-references

Avoid SaaS marketing gloss, over-decorated AI chat chrome, distracting motion, gradient-heavy launch-page styling, and assistant UI that competes with the conversation. The product should not feel like a clone of a generic hosted chatbot, a terminal-only developer tool, or a dense admin console.

## Design Principles

1. Keep the task in the foreground. Chrome, controls, and state indicators must support the conversation rather than decorate it.
2. Make local control visible. Projects, workspaces, permissions, provider state, and artifacts should be legible at the moment they matter.
3. Prefer earned familiarity. Use standard product patterns for navigation, drawers, menus, forms, and modals unless a workflow needs a custom affordance.
4. Surface agent state clearly. Streaming, tool activity, pending interactions, queued turns, and errors should be understandable without reading logs.
5. Stay restrained by default. Use the accent for primary actions, selections, and status; reserve stronger visual treatments for warnings, permissions, and active work.

## Accessibility & Inclusion

Target WCAG AA. Future design work should preserve keyboard-first workflows, readable contrast in light and dark themes, responsive and mobile-safe layouts, visible focus states, semantic controls, and reduced-motion alternatives for any animation.
